## Existing integration

Voice API combines authored JSON. Existing `startTrial` owns protected equipment and class rewards.

- Add a pure personal access/assembly ledger. Only five permanent matching shards can assemble. No shard consumption or automatic class unlock. Preserve old access by its earned CLASS, never mis-map old region IDs onto the new classes. Existing unlocked classes remain accessible. Future Pyromancer cannot open an absent trial. New Necromancer assembly requires campaign completion.
- Keeper introduction, short lore branches, assembly and progress explanation are recording-ready stable IDs. Reuse shared authority and presentation; assembly requests apply independently to each present player using their own saved shards. Persist Hall conversation progress separately from campaign checkpoints.
- Replicate room transitions and shared Keeper state; keep local shard counts local. Do not silently send a party into unsupported unsynchronized trials: retain explicit existing trial entry constraints and test them.
- Add first-shard Hall directions now the destination exists. Keep trial mentor/combat overhauls explicitly open unless fully implemented and verified in this batch.
